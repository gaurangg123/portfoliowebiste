One platform for knowledge discovery, requests, an AI chatbot, approvals and leaderboards.

Make organizational knowledge easier to discover and use through a shared platform with role-based access. It serves four roles: Viewer, User, Admin and Champion.

Business Sheet

M-05Company project·Data engineering

Enterprise Data Migration

Migrated data, dashboards and their underlying data sources from SQL Server to Snowflake.

Problem
Different types of enterprise data held in traditional Microsoft SQL Server environments needed to move into a cloud data warehouse, Snowflake.
What I built
This was a team initiative, and I was one of its contributors.
How it works
Data moves from the SQL Server sources through extract, transform, validate and load stages into Snowflake, with Azure Data Factory as supporting infrastructure. Validation is its own stage, so problems surface before data reaches the warehouse. Dashboards and their underlying data sources were migrated too.
Results
Completed The migration is complete. Data moved from traditional Microsoft SQL Server environments into Snowflake, and the initiative also covered dashboards and their underlying data sources.

06//How I work

Inside my engineering workflow.

From a business question to a solution people use, in five stages. Select a stage to see what happens there. This is how I approach engineering work. The examples point to documented projects; not every activity applies to every project.

Stage 01 of 05

Understand business requirements, data sources, constraints and desired outcomes, before choosing any technology.

What I do here

  • Clarify who will use the solution, and what decision or task it should support
  • Read the requirements or specification closely
  • Look at the data that exists, where it lives and how reliable it is
  • Agree what a good outcome looks like

Tools & techniques

  • SQL
  • Python
  • Requirement documents

In practice

The Knowledge Portal began from a supplied functional specification, which set out its roles and capabilities. See the project

Stage 02 of 05

Plan the architecture, technology stack, data flow and implementation strategy, so the build has a clear shape.

What I do here

  • Map how data moves from its source to the people who use it
  • Decide where data is stored and how it is shaped
  • Split the work into stages that can each be checked
  • Plan where people review what AI produces

Tools & techniques

  • Snowflake
  • ETL / ELT
  • Data Pipelines
  • Data Warehousing

In practice

In the Data Migration initiative, validation is its own stage between transforming and loading, so problems surface before data reaches Snowflake. See the project

Stage 03 of 05

Develop data pipelines, applications, AI capabilities and automation workflows that people can actually use.

What I do here

  • Build pipelines and transformations
  • Develop the application and its interface
  • Add AI capabilities such as chatbots, extraction or matching
  • Automate steps that used to be repeated by hand

Tools & techniques

  • Python
  • SQL
  • Snowflake

Stage 04 of 05

Validate functionality, data quality, performance, accuracy and reliability, and keep people in the loop where AI is involved.

What I do here

  • Test features and fix defects
  • Check data quality before it is loaded or shown
  • Evaluate AI output and keep a human review step
  • Confirm the solution meets the requirements

Tools & techniques

  • Model Evaluation
  • Testing and debugging

In practice

Contract Intelligence presents extracted clauses and obligations as a summary for the legal team to review: it supports their decisions rather than making them. See the project

Stage 05 of 05

Deploy the solution, monitor its performance and continuously improve it.

What I do here

  • Collect feedback and questions
  • Refine the solution in small iterations
  • Document it so others can run it
